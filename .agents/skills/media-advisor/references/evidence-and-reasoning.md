# Media / Taste Evidence and Reasoning

This guide keeps taste explanations grounded in the user's reactions to
individual works rather than in a catalog, genre stereotype, or generated
review.

## Build the smallest evidence set

Retrieve only:

- work pages containing the user's actual reactions;
- taste observations and their supporting work links;
- exceptions, contradictions, dated evolution, and selected review pages;
- cross-vertical pages only when they explain a shared experience or what the
  user learned, while leaving those claims with their owners; and
- derived comparisons only as labeled recommendations, never as independent
  evidence.

For every candidate work or pattern, ask:

| Question | Why it matters |
| --- | --- |
| Did the user actually experience it? | Metadata or a recommendation is not a reaction. |
| What did the user say they responded to? | Completion and ratings do not explain taste by themselves. |
| Is the pattern supported by independent works? | One work or repeated summaries cannot establish recurrence. |
| What is the scope? | A game mechanic, film style, music period, or current phase may not generalize. |
| Are there exceptions or conflicts? | Outliers improve recommendations and prevent rigid rules. |
| When was the reaction recorded? | Taste can evolve, and old context may be historical. |

Use language such as:

- **Supported:** “The work page records that the user liked...”
- **Scoped:** “Across these described works, the evidence supports...”
- **Provisional:** “A reviewable pattern suggests..., but the evidence is thin.”
- **Conflict:** “This work is an exception to the usual reaction...”
- **Derived:** “This candidate is probably a fit because..., although...”
- **Unknown:** “The vault records consumption but not a personal reaction.”

## Consumption versus reaction

A person may finish a work and dislike it, abandon a work and value part of it,
watch a work for someone else, or consume something without forming a durable
opinion. Preserve only the distinction that helps future context. Do not infer
liking, preference, or emotional meaning from state alone.

Ratings can be included when the user uses them, but a number is not a reason
and should not replace the user's words. External reviews and plot summaries
can identify a work but cannot stand in for the user's reaction.

## Pattern support

An explicit user statement such as “I usually prefer slow-burn science fiction”
can support a scoped user-stated preference even before work examples exist.
Otherwise, an agent-inferred recurring pattern should have reactions to more
than one independently meaningful work or context and should remain reviewable
until the user resolves it. Diversity of works and reasons matters more than a
source count. Several generated summaries of one movie are still one piece of
evidence.

A pattern explanation should name the supporting works and the observed reason,
not just list genres. Avoid converting a pattern into identity, psychology,
morality, ideology, or a universal rule.

## Exceptions and evolution

Keep a pattern and its exception together but distinguish them. “Usually avoids
grind-heavy progression, but loved one game for its environmental storytelling”
is more useful than deleting either side. A changed reaction may indicate taste
evolution, a different medium, a different mood, or a context-specific choice.
Use dates and preserve earlier evidence until the distinction is clear.

## Recommendations

A recommendation should be a transparent comparison:

1. identify two or more evidenced reasons the candidate resembles works the user
   liked or avoids reasons attached to disliked works;
2. identify conflicts, missing evidence, and any important difference in medium
   or context; and
3. state a conditional conclusion such as “probably yes,” “possible fit,” or
   “uncertain,” with no claim of certainty.

A recommendation is derived advice. It cannot prove a new preference, verify a
work reaction, or promote a pattern into `core/`.

## Privacy and cross-vertical boundaries

Do not infer a user's political beliefs, religion, sexuality, ethnicity,
medical or mental-health condition, identity, intelligence, personality, or
morality from what they consume. If a user explicitly supplies a sensitive
personal connection, keep it narrowly scoped and easy to remove rather than
using it as an explanation for unrelated taste.

Learning owns what changed in the user's understanding. Relationships owns the
meaning of a shared viewing or recommendation exchange. Writing owns an
article's communication behavior. Media / Taste owns the reaction and its
broader taste evidence.

## Insufficient evidence

When the vault is thin:

1. report the reaction or exposure it actually records;
2. say which pattern or reason is not established;
3. offer a generic or conditional recommendation only if useful; and
4. avoid adding a page unless the user supplies a meaningful reaction or asks
   for future retention.

“No meaningful Media / Taste update” is a valid result when a source adds no
personal reaction, only repeats an existing work, or supplies only external
metadata.
